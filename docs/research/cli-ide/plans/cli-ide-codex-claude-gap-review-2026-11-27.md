## 当前不足与改进建议

### P0 · 交付终态需要绑定可验证的工作区事实

VERIFY01 已在独立校验器核对候选文件摘要和实际生成状态，并要求生成与行为验收同时通过。常规编码路径已有写入回执与复查提示。下一步把这两套证据接到用户真正看到的结果上。先为明确声明交付路径的工作流增加由宿主生成的交付摘要，关联 `sessionId`、`turnId`、文件读回和已执行检查。CLI JSON、VS Code 和 JetBrains 消费同一份摘要，能明确显示“写入已确认”“检查通过”“交付未验证”。验收覆盖占位文件、写入后被撤回、测试未运行，以及正常交付四种场景。普通问答继续按其原有终态返回。[候选比对](../../../../packages/cli/scripts/verify01-native-task-checker.mjs#L108) · [严格通过条件](../../../../packages/cli/scripts/verify01-native-task-checker.mjs#L619) · [编码提示](../../../../packages/cli/src/lib/coding-task-guidance.js)

### P0 · 流式错误应给出可操作的原因

`.163` 已修复 OpenAI 兼容流的显式错误帧被当成成功的问题。当前 `_openaiReduceLine` 检测到 `error` 后调用无参错误构造器。直接送入三种合成错误帧，`insufficient_quota`、`rate_limit_exceeded`、`server_error` 均返回 `CC_CHAT_COMPLETIONS_STREAM_FAILED`、同一提示和 `noReplay: true`。IDE 和自动化因此无法区分额度、限流和上游故障。建议复用已有 HTTP 错误处理的脱敏逻辑，以协议字段映射少量稳定类别，缺少可信分类时保持未知。保持显式失败的 `noReplay`，保留是否已经收到输出和用量是否可知。通过 `cc chat`、`cc agent -p`、`cc stream` 和 IDE 检查同一归因。验收先重放 `verify-18` 的已归档错误形态，再用合成额度、限流和上游故障帧检查退出码、终态、无重复请求及脱敏。[流归约器](../../../../packages/cli/src/runtime/provider-stream-state.js#L307) · [现有错误构造器](../../../../packages/cli/src/lib/stream-retry.js#L30) · [HTTP 错误处理](../../../../packages/cli/src/lib/provider-http-error.js) · [Codex 0.172.0](https://github.com/openai/codex/releases/tag/rust-v0.172.0)

### P0 · 限制普通 `read_file` 的读取成本，保留分页和压缩连续性

`@` 文件展开已有 `isFile()` 判断和默认 100 KiB 上限。普通 `read_file` 分支只先排除目录，随后同步读取全文，再构建分页。代码上仍有非普通文件阻塞和大文件分页时整文件进入内存的风险。这是源码确认的边界，尚无本轮跨系统挂起测试结果。建议先让普通读文件复用有界读取，打开后验证实际文件类型，支持取消和稳定错误码。保留行号分页、UTF-8、Notebook、哈希行及读回凭据的语义。用原 `verify-05` 页序列和 `verify-29`、JetBrains 首次旅程的压缩输入验证同一文件版本的读回与恢复，再加大文本、非普通文件和取消夹具。记录读取字节数、耗时、压缩提交与降级原因。[普通读取](../../../../packages/cli/src/runtime/agent-core.js#L5840) · [引用展开](../../../../packages/cli/src/runtime/file-ref-expander.js#L263) · [压缩内核](../../../../packages/cli/src/lib/context-memory-kernel/live-compaction.js) · [Claude Code 2.1.332](https://github.com/anthropics/claude-code/releases/tag/v2.1.332)

### P1 · 跨入口恢复应统一验证工作目录、额外根和沙箱

当前已有可靠的历史读取、计划权限恢复和后台工作树映射。普通 `agent --resume` 的源码仍从本次调用的目录、`--add-dir` 和沙箱选项计算执行上下文，App Server 适配器也有自己的沙箱默认值。尚需用真实进程核验从不同目录恢复同一会话时，各入口实际采用的执行范围。建议在 CLI 已验证的会话快照上保存工作区身份、宿主路径类型、额外根和沙箱意图。恢复时按当前托管策略重新核验，明确显示本次显式覆盖和无法映射的旧路径。审批继续按轮次绑定。验收至少覆盖不同目录恢复、`--fork-session`、旧会话、额外根移动、策略收紧，以及 Windows 客户端连接 Linux 宿主。[CLI 沙箱与附加根](../../../../packages/cli/src/commands/agent.js#L1382) · [headless 恢复](../../../../packages/cli/src/runtime/headless-runner.js#L1239) · [会话快照](../../../../packages/cli/src/lib/session-host-snapshot.js) · [App Server 适配器](../../../../packages/cli/src/lib/app-server/cli-agent-kernel-adapter.js#L89) · [Codex 0.172.0](https://github.com/openai/codex/releases/tag/rust-v0.172.0)

### P1 · IDE 应显示会话的持久化和恢复状态

VS Code 已为本轮持久化失败生成带阶段的诊断，JetBrains 已支持分页消息的截断标记。仍需统一验证历史只载入部分、暂时载入失败、写入失败、等待用户或 MCP 输入时，两端提示是否一致。建议在既有会话投影中提供持久的状态及来源，IDE 重连后可重新显示，并区分单条大消息截断和整段历史载入不完整。测试以相同会话 ID 重启两端宿主，核对历史页、等待原因及是否需要显式重试。若 App Server 会话导航采用 Codex 适配，沿用现有 `recency_at + useStateDbOnly`。上次 0.172.0 冷扫描两端均能翻页，但同时间条目没有按方向反转，继续保留现有切换门槛。[VS Code 诊断](../../../../packages/vscode-extension/src/chat/agent-diagnostics.js#L81) · [JetBrains 分页](../../../../packages/jetbrains-plugin/src/main/java/com/chainlesschain/ide/SessionTranscriptPage.java#L89) · [会话投影](../../../../packages/cli/src/lib/session-projection.js#L177) · [Codex 冷扫描记录](./cli-ide-codex-claude-learning-review-2026-11-22.md#codex-01720-冷首次扫描续验) · [Claude Code 2.1.332](https://github.com/anthropics/claude-code/releases/tag/v2.1.332)

### P2 · MCP 按需搜索应延伸到可选 stdio 进程启动

项目已经支持工具搜索按需展开和发现缓存。`setupMcpFromConfig` 登记目录后仍立即等待 `mcpClient.connect`，所以减少模型工具定义与减少启动子进程是两项独立工作。先给已缓存且非启动必需的 stdio MCP 试点按需建连，首次调用前重新经过现有执行授权与生命周期管理。同一服务并发调用合并启动。缓存或权限变化时重新核验。以空配置、一台慢服务、五台可选服务量启动进程数、首轮可输入时间及首次工具延迟，再决定默认范围。Claude Code 的 MCP Skill（Beta）可留到此后评估，届时明确来源和内联命令的审批边界。[配置连接](../../../../packages/cli/src/runtime/mcp-config.js#L736) · [目录缓存与建连](../../../../packages/cli/src/harness/mcp-client.js#L1648) · [工具搜索](../../../../packages/cli/src/runtime/mcp-tool-search.js) · [Codex 0.172.0](https://github.com/openai/codex/releases/tag/rust-v0.172.0) · [Claude Code 2.1.332](https://github.com/anthropics/claude-code/releases/tag/v2.1.332)
